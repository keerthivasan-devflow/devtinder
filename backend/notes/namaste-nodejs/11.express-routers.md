## Logout Behavior Without Authentication

No active session - The server checks for a valid session or token. If none exists, it simply responds with a message like “No user is currently logged in” or returns a 401 Unauthorized/400 Bad Request.

Graceful success - Some apps return a success response anyway (e.g., “Logged out successfully”) even though no session was active. This avoids leaking information about session state.

Error response - Other implementations explicitly throw an error, indicating that logout cannot be performed because the user is not authenticated.

## Why this matters

- It prevents confusion about whether a user was logged in.
- It ensures consistent handling of session management.
- It avoids potential security leaks e.g - revealing whether a particular user is logged in
